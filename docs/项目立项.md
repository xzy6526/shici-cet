# CET 四六级背单词项目立项

## 新项目启动报告

项目名称：CET 四六级背单词

项目类型：本地优先的移动端优先 Web 学习工具

项目一句话说明：为 CET-4 考生提供按复习优先级安排、以主动回忆为核心、操作短而顺的背词流程。

项目目标：验证用户是否愿意每天持续背词，以及“到期复习优先 + 分级反馈 + 本地断点续学”是否能形成稳定的最小学习闭环。

目标用户：CET-4 考生；第一版主要供项目发起人和同学使用。

建议路径：`D:\CodexProjects\01_进行中的项目\四六级单词`

最终交付物：一个可在手机和桌面浏览器打开的 CET-4 背词网站，首版完成首页、背词未揭晓、答案展开、今日完成四个核心状态及本地进度保存。

是否发现已有项目：发现相关开源项目和算法，但没有发现可以直接覆盖本项目产品边界、中文 CET-4 内容和交互要求的成熟项目。

可复用资源：Anki 的间隔复习思路、Open Spaced Repetition 的 FSRS 实现、Tartarus 的“到期工作优先 / 本地优先”设计、Word Wind 的 CET-4/CET-6 词库与音标交互参考。

当前状态：已立项；核心 UI 已完成，已接入 4025 条来源可追溯的 CET-4 词汇，例句/音标内容仍待审核补充。

## 项目边界

### 包含

- CET-4 首页与考试倒计时；
- 今日复习和新词数量展示；
- 到期复习优先的学习队列；
- 单词发音、认识程度选择和分级答案；
- 收藏、撤销、下一个和今日完成反馈；
- `localStorage` 本地即时保存与断点恢复；
- 移动端、桌面端、深色模式和减少动态效果支持。

### 不包含

- CET-6 正式内容、完整真题词库和词频结论；
- 账号、云同步、服务端数据库；
- AI 老师、社区、排行榜、徽章、积分和提醒；
- 独立数据页、随机背词、拼写专项和完整离线系统。

### 调研结论

优先级应为“组合成熟思想和原生能力”，而不是直接接管大型项目：

1. 第一阶段用现有 Node 原生静态服务器、浏览器原生模块、CSS 动效和 `localStorage` 完成四个核心状态；
2. 学习数据字段保持与后续 FSRS 兼容，例如 `state`、`due`、`stability`、`difficulty`，但在真实需要前不安装调度库；
3. 真实 CET-4 词库接入前，必须单独核验来源、许可证、词义、例句和出处字段；
4. 如果最小闭环验证成功，再评估 `ts-fsrs` 或独立调度模块，并用实际复习记录测试而不是凭感觉升级。

## 技术方案分析

### 推荐方案

采用“原生 Web UI + Node 本地服务器 + `localStorage`”的首版方案。页面层按首页、学习页、完成页和可复用单词卡拆分；状态层只保存设置、队列位置、词条结果和收藏；词条内容继续放在 `src/words.js`，不把内容和状态混在一起。

### 推荐理由

- 与现有 `server.mjs` 和零依赖 `package.json` 直接兼容；
- 无构建等待和额外包体，适合先验证操作流畅度；
- `localStorage` 足以支持第一版断点恢复，不需要账号或数据库；
- CSS `transform`、`opacity` 和原生媒体查询可覆盖要求的短动效、深色和减少动态效果；
- 后续仍可把状态层替换为 FSRS，而不必重写页面交互。

### 主要风险

- 示例词条不能证明真题体系有效，词库质量是产品验证的关键外部依赖；
- 本地数据只能在当前浏览器保存，清理站点数据会丢失进度；
- Web Speech API 的发音质量和可用性依赖浏览器与系统；
- 如果过早引入完整框架、后端或 FSRS，可能增加维护成本并掩盖核心交互问题；
- GitHub 调研本次未能通过 CLI 克隆仓库，许可证和实现细节不能超出页面证据推断。
